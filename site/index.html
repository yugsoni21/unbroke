How it works

From a provider's changelog to your exact line.

Three steps that used to be a person reading release notes, grepping a codebase and guessing.

01 · WATCH

It knows how every API looked six months ago.

Unbroke reads each provider's published spec and its history, then rates every change from the caller's side: a removed field is a warning, a removed endpoint is breaking, a new optional value is noise.

02 · FILTER

Only what touches your code.

It finds which endpoints your code calls and whether the changed field is used next to the call.

03 · PINPOINT

Any language it can read.

URLs, route strings and SDK calls, found by reading source. Nothing is ever run.

04 · MEND

A fix, not a ticket.

The smallest edit at each call site, on a new branch, kept only if your tests pass.

+ 'allowed_payment_method_types' => […]
05 · GATE

A CI check that never lies.

Fails when a change affects your code. Says "could not check" instead of a false green.

FAQ
Questions, answered plainly.

    

      
Which APIs does it watch? 
35 public APIs that publish an OpenAPI or Swagger specification, including Stripe, GitHub, OpenAI, Twilio, Cloudflare, Datadog, Kubernetes, Plaid, Okta, Sentry, PayPal and Adyen. If a provider publishes a spec, adding it takes one entry.

      
How does it know a change affects my code? 
It compares the provider's spec today with how it looked on a past date, finds the endpoints your code calls, and checks whether the field that changed appears next to the call. Calls where it can't see the field are listed separately and ranked lower, so you can see how sure it is.

      
Does my code leave my machine? 
Not for scanning. The fix step sends only the affected files to the model you configure, using your own key, and you can preview exactly what would be sent first.

      
What if a proposed fix is wrong? 
It lands on its own branch, your tests decide whether it's kept, and you review it like any pull request. Unbroke reports what the provider's published spec says, so it's worth confirming a change against their changelog too.

      
Is it ready to use? 
It's early. The change engine and the scanner run on real projects today and are open source. The fix agent works end to end and is still being tested on real codebases. Some libraries with their own call style aren't recognized yet, and Unbroke says so instead of reporting you as safe.
