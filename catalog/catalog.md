## Not located

Well-known companies whose public OpenAPI spec was not found. That is not proof none exists.

- **Shopify**: Admin API is GraphQL-first; no REST OpenAPI located
- **Salesforce**: No stable public spec file. Commerce Cloud (SCAPI) publishes OpenAPI files, but in folders named after each release (apis/shopper-products-oas-1.13.0/), so the path changes every version; the Marketing Cloud file was last updated in 2019; the core platform API (sObjects) only has a beta spec generated per customer org; no Connect REST, Data Cloud or Agentforce file was found.
- **Zoom**: The only published OpenAPI file dates from 2018 and is out of date.
- **Amazon Web Services**: no first-party OpenAPI; per-service Smithy models instead
- **Google Cloud**: publishes Discovery documents and protobufs, not OpenAPI
- **Microsoft Azure**: per-service specs in a very large multi-service repository; not yet added
- **Gusto**: not located at the paths tried
- **Brex**: not located at the paths tried
- **WooCommerce**: No official OpenAPI known (REST docs hand-written; woocommerce-rest-api-docs is docs source). Only briefly checked.
- **QuickBooks / Intuit**: Intuit states the QBO API is not OpenAPI compliant; only community gists exist.
- **Freshworks (Freshdesk/Freshsales)**: Not checked in detail: no public spec known; likely repositories not found.
- **Adobe Acrobat Sign**: adobe-sign/AdobeSign-OpenAPI json/ folder is per-resource Swagger 1.2 (not 2.0/3.x) per Adobe docs; no unified 2.0/3.x spec found.
- **Klarna**: No official spec file found; only api-evangelist/APIs.guru third-party copies.
- **Wise (TransferWise)**: No official OpenAPI; transferwise/api-docs is archived markdown docs. Only third-party mirrors.
- **Checkout.com**: No spec found: api-reference.checkout.com/swagger.json 404, no official spec repo located.
- **Rippling**: Not checked in detail: likely repositories 404, no public spec known.
- **Increase**: https://api.increase.com/openapi.json returns 401 (reportedly the spec URL but needs auth); no public spec repo (Increase/increase-openapi 404). Stainless SDK repos reference hash-named spec URLs that are not stable.
- **Tink**: No official spec; only community ulfsa/tink-openapi.
- **TrueLayer**: No public spec found.
- **Unit**: unit-finance/openapi-unit-sdk openapi.json (3.0.2, 0.02 MB) is a thin index of 117 paths with 0 inline operations ($ref to other files); not usable as a single spec.
- **Marqeta**: marqeta/marqeta-openapi has real specs (yaml/CoreAPI-3.0.40.yaml, 324 paths, 424 ops, 1.86 MB) but each release is a new numbered file (CoreAPI-3.0.1 ... 3.0.40), so there is no stable path and no per-file history.
- **Avalara AvaTax**: Avalara/Swagger and the usual spec URLs 404; repo layout changed and no verified current spec found.
- **Amadeus**: amadeus4dev/amadeus-open-api-specification is real (Swagger 2.0, one file per API) but the org is marked DEPRECATED, Self-Service portal reportedly decommissioned July 2026, and files are stale (Flight Offers Search last touched 2024-03).
- **Booking.com**: Not checked in detail: partner API is behind login, no public spec known.
- **Bill.com**: Not checked in detail: no public spec repo known.
- **Groq**: No published OpenAPI spec found: api.groq.com/openapi.json, console.groq.com/docs/*openapi* all 404; only third-party tryAGI/api-evangelist copies. OpenAI-compatible, so OpenAI spec roughly applies.
- **Vultr**: Spec exists (SDK generated from www.vultr.com/api) but openapi.json URL returns 403 to curl (bot protection) and no repo copy found; vultr-python-client contains only generated code.
- **Scaleway**: Dozens of per-product specs on developers.scaleway.com, no single file; only a third-party mirror (Plana-Solutions/spec-mirror-scaleway).
- **OVHcloud**: Swagger 1.2-style API listing at eu.api.ovh.com/v1/ (index of many per-service docs, no paths in a single OpenAPI 3/Swagger 2 file).
- **Railway**: GraphQL only (backboard.railway.com/graphql/v2).
- **Heroku**: Platform API described by a JSON Hyper-Schema (api.heroku.com/schema returned 400 without proper Accept header), not OpenAPI/Swagger.
- **New Relic**: NerdGraph is GraphQL; REST v2 has no published OpenAPI file.
- **Postman API**: No public OpenAPI file found (api.getpostman.com/openapi.json 404).
- **Mux**: Spec only embedded in docs text page (mux.com/docs/api-reference/data.txt, JSON in a markdown code fence, ~0.27 MB), not a downloadable OpenAPI file; no spec in muxinc repos (SDK .stats.yml has no URL).
- **Cloudinary**: No public OpenAPI spec found at the usual docs URLs or via search; SDK-only.
- **Segment (Twilio Segment)**: Public API spec behind docs.segmentapis.com download; api.segmentapis.com/openapi.json returns 401; no repo copy (SDK repos are generated).
- **Contentful**: No official OpenAPI spec for CMA/CDA; only third-party api-evangelist copies.
- **Sanity**: No published OpenAPI file found (HTTP API docs only; GROQ/GraphQL).
- **Strapi**: Self-hosted; spec generated per project by a plugin, no central public file.
- **Fastly**: Official specs live in a private/unlocated repo; only third-party per-product copies (api-evangelist/fastly) and developer.fastly.com/reference/api/openapi.json 404.
- **Terraform Cloud / HCP Terraform**: API docs are hand-written JSON:API pages; no OpenAPI file published.
- **HashiCorp Vault**: OpenAPI is generated at runtime from a running server (/v1/sys/internal/specs/openapi), not a published file.
- **Hasura**: GraphQL engine; no static REST OpenAPI spec (metadata API only documented in prose).
- **Snowflake REST**: Split into ~50 per-resource YAMLs in snowflakedb/snowflake-rest-api-specs/specifications (account.yaml, database.yaml, ...); no single file. Could add up to 3 if wanted (e.g. sqlapi.yaml).
- **Appwrite**: Specs not at the expected app/config/specs path on default branch; not located.
- **Sonar (SonarCloud)**: Web services listing at /api/webservices/list is a custom JSON, not OpenAPI.
- **Stability AI, Fireworks, Together AI, dbt Cloud, Airbyte, Ory**: The usual spec locations returned 404; no verified public spec found.
- **Vonage / Nexmo**: Official specs lived in nexmo/api-specification, which now returns 404; developer.vonage.com spec download URLs return 400/redirect. Only third-party mirrors (api-evangelist) found.
- **Bird / MessageBird**: MessageBird/openapi-specs contains only small AI/SMS specs last touched 2022.
- **Plivo**: No public OpenAPI file found.
- **Bandwidth**: Bandwidth/api-specs (source of truth) is not public; Bandwidth/api-docs/site/specs is archived and untouched since Oct 2023.
- **Mailchimp Marketing**: https://api.mailchimp.com/schema/3.0/Swagger.json is a Swagger 2.0 root whose paths are all external $ref files (e.g. '/' -> {$ref}), not self-contained, so it is not a single downloadable spec.
- **Mailjet**: No public OpenAPI file found (api.mailjet.com/v3/openapi.json returns 500).
- **Iterable**: No public OpenAPI file found; docs site is login/403 for scripted fetch.
- **OneSignal**: OneSignal/api api.json is a real OpenAPI 3.0 file (25 paths) but last touched 2023-08, over 3 years stale and small.
- **Pusher**: No public OpenAPI file found.
- **PubNub**: pndsn/pubnub-api has no OpenAPI file; none found.
- **Courier**: api.courier.com/openapi.json returns 403; openapi.documented.yml path from docs returns 404 / not valid YAML.
- **Reddit**: No official OpenAPI file.
- **YouTube Data API**: Google Discovery document only (not OpenAPI), confirmed not in scope.
- **Google Workspace APIs**: Google Discovery documents only, not OpenAPI.
- **Vimeo**: vimeo/openapi api.yaml is valid OpenAPI 3.0 (181 paths) but the repo is archived and the file last changed 2019.
- **Linear**: GraphQL only.
- **Airtable**: No official OpenAPI spec published.
- **Atlassian Statuspage**: swagger.json URLs return 401/404; no public file.
- **Opsgenie**: opsgenie/opsgenie-oas swagger.json is valid (104 paths) but last changed 2021-02; product is being sunset.
- **Atlassian Compass**: Valid OpenAPI but only 8 paths; too small to be useful.
- **Freshdesk**: No official OpenAPI file; only a community forum request.
- **Help Scout**: No public OpenAPI file found.
- **Kustomer**: Spec is fragmented across about 10 ReadMe registry files with duplicate UUIDs per name; the 'Core Resources' fragments (86 and 97 paths) exist but it is unclear which is current.
- **Dropbox (core API)**: Official spec (dropbox/dropbox-api-spec) is Dropbox's own Stone format, not OpenAPI. Dropbox Sign is included separately.

- **RingCentral**: ringcentral/ringcentral-api-docs specs/ringcentral_openapi3.json is valid OpenAPI 3.0.1 (242 paths, 4 MB) but git history shows a single commit dated 2021-03; looks stale or force-pushed, no useful diff history. Could be reconsidered as a URL-hosted snapshot.
- **Telegram Bot API**: No official OpenAPI spec; community specs not found at tried URLs.
- **Mattermost**: mattermost-api-reference keeps the spec split across many files in v4/source (no single bundled file); the api.mattermost.com static YAML URL returns HTML.
- **Rocket.Chat**: RocketChat/Rocket.Chat-Open-API is split into about 12 files by area (each a separate spec), not one main file.
